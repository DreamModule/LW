# Лабораторная работа №3: Проектирование формата файлов

**Цель работы:** Изучение принципов создания и обработки бинарных (двоичных) файлов на языке программирования высокого уровня (ЯВУ).

---

## 🛠 Общие требования и ограничения

* **Тип данных:** Все данные обрабатываются как «сырые» бинарные данные (октет/байт x86).
* **Запрещенные функции:** Использование функций текстового ввода-вывода (`fgetc()`, `readLine()`, `split()`, `fprintf()` для данных и т.д.) — **Штраф -2 балла**.
* **Рекомендуемые функции:** Аналоги `fread()` для чтения и `fwrite()` для записи.
* **Реализация:** Кодер и декодер могут быть как отдельными модулями, так и одной программой с выбором режима через ключи командной строки (например, `-c` и `-d`).

---

## 📋 Задание №1: Нулевая версия формата (V0)

Разработать программу-кодек для базового архивирования файла без сжатия.

### Спецификация формата (Таблица Л3.1)

| Смещение (байт) | Размер (байт) | Описание поля |
| :--- | :--- | :--- |
| 0 | 6 | **Сигнатура:** Уникальный идентификатор формата. |
| 6 | 2 | **Версия:** Беззнаковое 16-битное целое (для Л3.№1 равно `0`). |
| 8 | 8 | **Длина файла:** Исходный размер $n$ в байтах (uint64). |
| 16 | $n$ | **Данные:** Содержимое исходного файла «как есть». |

**Функционал:**
1. **Кодер:** Создает архив $R$ из файла $Q$.
2. **Декодер:** Проверяет сигнатуру и версию, восстанавливает файл $\tilde{Q}$. Результат должен быть идентичен оригиналу ($Q = \tilde{Q}$).

---

## 📋 Задание №2: Проектирование расширенного формата (V1+)

Разработать структуру заголовка для продвинутого архиватора, поддерживающего метаданные алгоритмов.



**Обязательные поля заголовка:**
1.  **Сигнатура:** 6 байт (начало совпадает с сигнатурой из задания №1).
2.  **Версия:** Мажорная и минорная (например, 1.0 и выше).
3.  **Алгоритмы сжатия:** Два кода (для методов с учетом контекста и без него).
4.  **Защита от помех:** Код алгоритма контроля целостности.
5.  **Метаданные:** Возможность добавления служебных данных (таблицы частот и т.д.) без изменения структуры заголовка.
6.  **Длина файла:** Размер исходных данных в байтах.

*Примечание: Если алгоритм не используется, в соответствующем поле ставится `0`.*

---

## 📋 Задание №3: Реализация расширенного кодека

Разработать программу-кодек, реализующую формат, спроектированный в **Задании №2**.

**Требования к проверке:**
* Использование шестнадцатеричного редактора (Hex Viewer) для проверки заголовка.
* Сравнение файлов байт-в-байт (утилита `diff` в Linux или аналоги в Windows).
